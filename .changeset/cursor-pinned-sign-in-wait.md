A run pinned to a Cursor account no longer fails because `cursor-agent status` took more than 10 seconds on a busy host (#532). The pinned run now waits for that same status check until Cursor answers, the run is cancelled, or 120 seconds pass; with no answer it refuses with "Cursor did not confirm sign-in within 120s", and it still never starts on an unanswered or older answer and never moves to another account. Run admission passes the run's cancellation and the pin to the account probe through an optional argument of `probeCredentialProfile`; an explicit reviewer seat's account preflight does the same under the run's or the diff review's cancellation, and the spawn-time check waits only for a spec the engine stamped as an explicit pin. The status process belongs to a per-store coordinator: each caller waits on its own budget, one caller's cancellation ends only its own wait, the process is stopped as soon as no caller still waits for it (a positive it still returns afterwards is not kept, while a logged-out answer still revokes), and a Claudexor credential change answers pending waits unknown at once. The process does not carry the run marker of the run that started it, so cancelling that run no longer ends a status check another pinned run is still waiting for. Unpinned routing, Accounts, doctor and passes that carry no pin fact, such as the continuity summary, keep the 10-second decision; unpinned routing keeps the five-minute last-positive rule.
