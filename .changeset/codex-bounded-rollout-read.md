Codex rollout reads are bounded and never follow a link. The observed model, the rollout quota, the vendor failure and session continuity read the native rollout in fixed 1 MiB chunks up to the size captured at open, carrying at most one 8 MiB line, so a very large or newline-dense rollout no longer makes the engine materialize the whole file or abort; a longer line is never parsed and, when it carries the reader's marker, counts like a torn record. A rollout part that is a link, or lies below a linked `sessions` or date directory, is never read or copied: it is still located, and moving it to another account fails with a reason. The run's `CODEX_HOME` is canonicalized first, so a home under a linked directory such as macOS `/tmp` or `/var` keeps working, including moves out of the default home, which were refused before. A move compares homes by directory identity: two spellings of one store, such as the default home and the profile the accounts migration registers for it, are the same home and nothing is copied, and the copy refuses a destination that is its own source before truncating it. One cursor per run serves the model and the quota, so looking again for a model that is not recorded yet reads only appended bytes instead of the whole history. On a resumed session the observed model now comes only from the turn the app-server started, also when a goal continuation's next turn is recorded before the next read: codex records that turn's model seconds after the turn begins, and before this change a resumed run could report the previous turn's model as its own.
